# MarketFit Job Lens

[English](README.md) · 简体中文

一个 Manifest V3 的 Chrome 侧边栏扩展：读取你当前标签页里的职位描述，和你的 PDF 简历逐条对照，回答一个问题——**这份工作值不值得你花一个晚上去投**。

界面和分析结果都支持中文与 English。

它不是面试结果预测，不是法律意见，不做移民资格判断，也不会替你自动投递。

## 它给你什么

**先给结论。** 一个判断——可以直接投 / 值得投递 / 补齐后再投 / 建议先跳过——并且附上支撑它的计数（`4 项必需要求 · 1 项有证据 · 1 项部分满足 · 2 项缺失`）、投递这份工作的成本（改简历半小时、一个晚上、还是更久），以及最能改变结论的那一件事。

**把「筛人的」和「许愿单」分开。** 职位描述几乎每一行都写着「必须」。真正的硬性门槛，是招聘方不需要任何判断就能核对、且单独一条就能结束这次申请的东西——执照、安全审查、工作许可条件。其余都是加权项。结论跟着硬性门槛走，而不是数勾了几个框。

**雇主写明的条件，原样引出来。** 一句「不提供签证担保」在「匹配度」之前就决定了这次申请，所以它紧贴结论卡片下方。

**工作授权会真的改变结论。** 当雇主写明的条件与你选择的工作授权状态冲突时，结论会被下调，并且卡片上会写明**是被下调的、以及因为哪一条**。这是把两句自述的事实放在一起对照，不是对你法律身份的判定。默认值「未知」不触发任何判断。

**给的是计划，不是清单。** 行动按「什么时候做」分组并编号，分析要你做的每件事只出现一次。

**简历优化保持诚实。** 它可以重新组织、锐化你简历里已有的证据；但不会替你添加一项技能，不会把「参与」升级成「主导」，不会把团队成果写成你个人的，也不会编一个你没有的数字。

### 刻意不做的事

- **不给移民建议。** 不讲签证路径、配额、办理时长。这里没有任何政策数据，也无法核实模型「回忆」出来的东西——关于资格的一个自信的错误答案，比不回答更危险。它只报告雇主写了什么，剩下的留给你自己核实。
- **不做预测。** 不给面试概率，不给录用可能性。
- **不编造证据。** 每一条结论都必须引用你简历或职位页面里的一个文本块，无法解析的引用会被丢弃而不是照样显示。

## AI 服务与 API Key

选择一家，把 API Key 粘贴进侧边栏。**Key 只保留在当前打开的侧边栏里**，从不写入存储；首次请求前 Chrome 会单独询问是否允许访问该服务的域名。

| 服务 | 可选模型 | 去哪里创建 Key |
| --- | --- | --- |
| OpenAI | GPT-5 mini, GPT-5 | [platform.openai.com](https://platform.openai.com/) → API keys |
| Anthropic | Claude Opus 5, Claude Sonnet 5, Claude Opus 4.6, Claude Sonnet 4.6 | [platform.claude.com/settings/keys](https://platform.claude.com/settings/keys) |
| DeepSeek | DeepSeek V4 Flash, DeepSeek V4 Pro | [platform.deepseek.com](https://platform.deepseek.com/) → API keys |

真正卡住人的不是创建 Key，而是账户余额。**新建的 Key 如果账户没有余额，第一次调用就会失败**，报错看起来像是插件坏了。请先充值。Key 只在创建时显示一次，丢了就重新建一个。

## 本地运行

```bash
npm install          # 只有一个运行时依赖 pdfjs-dist
npm run vendor:pdfjs # 把 PDF 运行时复制到 vendor/
npm run check        # 静态检查 + 测试 + 全项目审计
```

然后打开 `chrome://extensions`，开启「开发者模式」，点「加载已解压的扩展程序」，选择本目录。

打开一个完整的职位详情页，点击扩展图标，上传可提取文字的 PDF 简历、选择目标市场与工作授权状态，选一家 AI 服务，然后点「用 AI 分析当前职位」。如果 Chrome 询问是否允许读取当前网站，同意那个单站点授权即可，MarketFit 会自动重试。

侧边栏标题旁显示当前加载的版本号。改动之后如果它和 `manifest.json` 对不上，说明扩展没有重新加载——**Chrome 会一直运行旧代码，直到你手动点重新加载**。

## 数据流向

在你点击「分析」之前，不会有任何数据离开本机。

- PDF 文件及其提取出的文字只存在于侧边栏内存中，从不写入 Chrome 存储。扫描件或纯图片 PDF 会被拒绝，因为本地无法可靠地提取文字。
- 只有在你点击「用 AI 分析当前职位」之后，才会抓取当前标签页。页面读不了时可以手动粘贴 JD，**你粘贴的文本不会被重新抓取覆盖**。
- 发送前会滤掉页面家具——导航、Cookie 横幅、相似职位栏、申请表单。侧边栏会显示滤掉了多少行，鼠标悬停可以看到具体内容：**看不见的过滤器，是你没法发现它删错了的过滤器**。
- 运行分析时，PDF 简历文字和抓取到的职位内容**只发送给你选择的那一家服务**——没有后端，没有埋点，没有中转。
- API Key 和模型选择框只在你选定某家 AI 服务后才出现，Chrome 也正是在那一刻请求该域名的访问权限。
- **「清除本地会话」**会清掉内存中的简历、职位、分析结果、API Key，以及所有已存报告。
- 跨会话保留的只有：界面语言，和历次分析的耗时。报告只在当前浏览器会话内存在，且**不含任何简历原文**——存储前会剥掉引用的源文本。

侧边栏里的**「预览可选 AI 负载」**会原样展示这次运行将要发送的内容，常见个人信息已做脱敏。

## 开发

没有构建步骤，没有开发依赖，全部是原生 ES 模块。

```bash
npm run check   # 唯一的关卡：静态检查 + 测试 + 审计
npm test        # 单元、集成与页面抓取测试
npm run audit   # 单元测试看不见的跨文件检查
```

审计覆盖的是跨文件才能发现的问题：manifest 指向了被删掉的图标、HTML 里改了 id 但 JS 没改、只加了一种语言的文案、没有转义的 `innerHTML`、出现了三家 API 之外的网络地址、渲染出的 CSS 类在样式表里没有规则、错误码缺少翻译、标记里有没挂翻译标记的可见文本、注入到页面里的抓取函数中存在会落入暂时性死区的 `const`。

其中大部分检查的存在，都是因为对应的 bug **真的发生过一次**。这个项目里有好几类失败是天生静默的——`t()` 找不到键时会把键名当文案渲染出来；一个把要求过滤掉的过滤器，看起来和「这份 JD 本来就没写这条」一模一样——所以防线必须是机械的，而不是靠提醒。每一条检查都经过反向验证：把 bug 放回去，确认它确实会失败。
